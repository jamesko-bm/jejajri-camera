# 제자리 카메라 웹

접속 즉시 카메라 권한을 요청하고, 허용되면 후면 카메라를 우선 사용합니다.
일반 사용 화면에는 촬영·업로드·분석 버튼이 없습니다.

- 카메라 움직임 감지 → 노란 테두리 제거 → `확인 중`
- 약 1초간 안정된 장면 → 한국어/영어 OCR 자동 실행
- 두 개 이상의 비교 가능한 청구기호 → `완료`
- 인접한 두 책에서 청구기호가 감소하면 **감소하기 직전의 왼쪽 책**에 노란 테두리
- 읽지 못하면 완료로 처리하지 않고 3초 후 자동 재시도
- 움직임 이후 도착한 오래된 인식 결과는 폐기
- 카메라 연결 오류에만 복구 버튼 표시

예: `100 → 410 → 300 → 400`에서는 `410` 책을 표시합니다.
기존 Python v0.1의 최소 이동 알고리즘과 목적이 다릅니다.

영상·사진은 브라우저 내부 메모리에서 처리하며 녹화·서버 전송·저장하지 않습니다.
Tesseract.js 5.1.1 및 OCR 모델은 CDN에서 다운로드합니다.
카메라는 HTTPS 또는 localhost에서만 동작하며 최초 브라우저 권한 허용이 필요합니다.
모델 초기 다운로드/인식 속도는 단말과 네트워크에 따라 달라집니다.

## 검증

```powershell
node --test test.mjs camera.test.mjs
node --check dist/app.js
```

22개 자동 테스트 통과: 감소 직전 책 선택, 동률/권차, 자동 재시도,
느린 누적 이동, 노출 변화, 동시 처리 방지, 오래된 결과 폐기,
OCR 후보 생성/경계 보정, 업로드·조작 버튼 제거, 기존 정렬 로직.
로컬 브라우저에서 카메라 시작 요청과 단순화된 화면을 확인했습니다.
이 환경의 카메라 권한 대기로 실제 책장을 카메라로 비춘 종단 검증은 하지 못했습니다.

## 범위

책장 한 단을 정면으로 비추는 베타입니다. 책 영역은 OCR 위치와 세로 영상 경계로
추정하며 객체 탐지 모델에 의한 정확한 책 분할이 아닙니다.
읽어낸 청구기호끼리 비교하므로 OCR 누락·오인식에 따른 오탐/미탐이 가능합니다.
현장 도서관의 실제 촬영 정확도는 검증 전입니다.
분류번호·저자기호·권차를 비교하며 별치/복본 등 도서관 고유 규칙은 미지원입니다.

`dist/`만 정적 사이트로 배포합니다. Python Streamlit 소스는 이전 실험 버전으로 보존되어 있습니다.

## GitHub 및 Vercel 배포

이 `web/` 폴더를 저장소 루트로 사용합니다. `vercel.json`이 정적 출력 `dist/`와
카메라 권한 헤더를 지정합니다. 빌드 과정이나 서버 환경변수는 필요하지 않습니다.
Vercel에서 저장소를 연결할 때 Framework Preset은 Other, Output Directory는 dist입니다.
프로덕션 주소를 누구나 이용하려면 해당 프로젝트의 프로덕션 Deployment Protection이
공개 접속을 막지 않아야 합니다. 실제 배포 후 비로그인 접속을 검증해야 합니다.
GitHub 저장소와 Vercel 프로젝트는 연결된 계정에서 생성합니다.
배포 상태와 공개 주소는 실제 배포 완료 후 확인해야 합니다.

참고: [Tesseract.js](https://github.com/naptha/tesseract.js),
[브라우저 카메라 권한](https://developer.mozilla.org/en-US/docs/Web/API/MediaDevices/getUserMedia).

## 실제 두 줄 라벨 지원 (2026-11-23)

- 첫 줄 분류번호와 바로 아래 저자기호를 공간적으로 연결합니다.
- `이64ㄷ`, `김94ㄱ2`, `허841ㅎ`, `진91ㅋ` 등 자모와 분리된 OCR 조각을 처리합니다.
- 신간 스티커와 저자기호가 없는 숫자 띠는 라벨 선택에서 제외합니다. `000`도 저자기호가 붙은 실제 청구기호이면 유효합니다.
- 전체 장면을 먼저 탐색한 후 각 라벨을 잘라 재인식합니다. 두 결과의 분류번호가 다르거나 신뢰도가 낮으면 해당 책의 비교를 보류합니다.
- 일부 라벨이 불확실하면 `확인 중`을 유지하면서 확실한 감소 지점만 표시합니다. 전체 비교가 가능해지면 `완료`가 됩니다.
- 별도 권차는 `v.2` 또는 `권2`처럼 명시된 줄만 사용합니다. 저자기호 끝의 숫자는 임의로 권차로 분리하지 않습니다.

제공받은 실제 사진을 2000px로 줄여 브라우저와 같은 Tesseract.js 엔진으로 로컬 검증했습니다.
6개 분류번호 후보를 찾았으며 `이64ㄷ`, `김94ㄱ2`, `허841ㅎ`, `진91ㅋ`를 읽었습니다.
`005.13 → 004.73`에서는 앞 책만 표시 대상으로 판별했습니다.
좁은 두 번째 책은 분류번호가 다르게 읽혀 비교 보류했고, 다섯 번째 책의 저자기호는 읽지 못했습니다.
따라서 사진 전체 인식 성공으로 보고하지 않습니다. 사진 원본과 OCR 출력은 공개 저장소에 포함하지 않습니다.
실시간 카메라의 현장 정확도 및 정확한 책 전체 경계는 추가 검증이 필요합니다.

## 카메라 인식 개선 (2026-11-23)

지원하는 기기에서는 3840×2160 카메라 스트림과 연속 자동 초점을 요청합니다.
장치가 제공하는 해상도가 더 낮으면 해당 해상도로 동작합니다.
전체 화면 탐색은 2000px로 수행하지만 재인식용 라벨은 원본 픽셀을 보존합니다.
읽지 못한 저자기호는 원본에서 줄 단위로 잘라 확대하고, 회색조·대비 보정·여백을 적용합니다.
첫 재인식이 실패하면 이진화 버전으로 재시도합니다. 전체 탐색이 실패하면 겹치는 두 확대 영역에서 다시 탐색합니다.
분류번호 재판정은 두 전처리 결과가 일치하고 신뢰도가 충분할 때만 허용합니다.
고정 DPI 설정을 제거하고 옆 책의 문자가 저자기호에 붙는 문제를 보정했습니다.

동일 사진의 6권 중 명확히 대조할 수 있는 저자기호는 5개입니다(좁은 두 번째 책 제외).
같은 파서에서 확대 재인식 사용 전 4개, 사용 후 5개가 일치했습니다.
새로 읽은 기호는 `이211ㅋ`입니다. 두 번째 책은 여전히 비교 보류입니다.
이는 사진 1장의 회귀 검증 결과이며 현장 인식률이나 모든 스마트폰의 성능 수치는 아닙니다.
원본 사진은 공개 저장소에 포함하지 않습니다.

전처리 참고: https://tesseract-ocr.github.io/tessdoc/ImproveQuality.html
